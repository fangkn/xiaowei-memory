# 运行时依赖来源

扩展运行时使用仓库内的 PDF 库、字体和图标，不从 CDN 加载 JavaScript 或字体。Node 开发依赖由 `package-lock.json` 锁定。

随扩展发布的 [依赖清单](../extension/DEPENDENCIES.json) 记录版本、来源、变换说明以及每个文件的 SHA-256；完整授权见 [第三方说明](../extension/THIRD_PARTY_NOTICES.md) 和各依赖的许可证文件。

```sh
node scripts/verify-vendor.mjs
```

该命令检查提交的依赖文件是否与清单一致，不联网，也不自动修改或下载文件。

## 更新流程

1. 从清单中的官方仓库或 npm 包取得明确版本的原始文件，记录下载地址和校验值。
2. 保留许可证。修改 fontkit 的 ESM 包装时，记录变换方法并核查完整工厂函数没有改变。
3. 更新依赖、对应 SHA-256 和变换说明，再运行 `npm test`、`npm run check`、`npm run build`。
4. 用包含中文、换行、链接、Unicode 表情、微博图片表情和照片的合成数据检查 PDF 文本与渲染结果。

## 当前可复现边界

当前字体由 Noto Sans SC 可变字体固定 `wght=400` 得到。原始下载的 Git 提交和 fontTools 版本没有记录，因此目前不能保证从上游重新生成完全相同的字体字节。仓库提交的静态字体和 SHA-256 是本版本的构建输入；安装包构建无需重新转换字体。

完整嵌入字体用于避免中文子集漏字，也会增加每个月 PDF 的基础体积。后续更换字体或引入子集前，必须验证旧归档和少见汉字。字体再生成工具链与上游提交锁定列在开发路线图中。
